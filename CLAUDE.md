# Stepout AI: working notes

- Tests (offline, scripted model): `./.venv/Scripts/python.exe -m pytest -q`. Run: `stepout` (chat in the browser), `stepout web` (chat at http://127.0.0.1:8765, no browser) or `stepout cli` (terminal); `stepout init`, `grant`, `remote`, `status` and `stop` are the other commands (README). In a checkout the command is `.venv\Scripts\stepout.exe`; `python -m stepout.app` and `python -m stepout.app web` still work. `STEPOUT_PORT` (else `PORT`, else 8765) changes the chat's port. Rebuild the page with `cd web && npm run build` (it writes `src/stepout/_web`, git-ignored). After a `git pull` that changes `pyproject.toml`, run `pip install -e ".[dev]"` again.
- **Orient with `docs/architecture.md`** (the map), then `docs/history.md` (what was decided and built), `docs/adr/` (the decisions), `docs/roadmap.md` (what is next, known debt). The wire between the page and the backend is `docs/ui-contract.md`; the vocabulary is `CONTEXT-MAP.md`; the look and its rules are `docs/design.md` (values only in `web/src/design/tokens.css`). Docs change in the same commit as behaviour.
- **Decisions:** one that is hard to reverse, surprising or a real trade-off gets an ADR in `docs/adr/` (short, dated, never rewritten into a different story: amend or supersede). Small changes are `git log`.
- **Adding a tool = one file in `src/stepout/capabilities/` (subclass `Capability`; its tool schema comes from the Action class via `tool_from`) plus one line in `ALL` in its `__init__.py`**, then name it in a Role's `tools` in `roles.py`. The Runner, Gate and model adapters learn it from the registry; `tests/support/echo_capability.py` is the minimal example. **If the tool can reach the network, set `reaches_web = True` on it**: the Gate then closes it for any Run that has read a file's contents.
- **Screening:** every message that is not a `/command` gets one cheap screening call first (`src/stepout/screening.py`, [ADR 0012](docs/adr/0012-the-front-door.md)). Its paid eval: `python -X utf8 -m pytest -m eval -s tests/test_live_screening.py` (labelled prompts: `tests/data/screening_prompts.jsonl`).
- **Memory:** `src/stepout/memory/` is the seam (in its `__init__.py`) ([ADR 0016](docs/adr/0016-memory-on-mem0-behind-the-seam.md)): Persona is the User's file (`<Home>/memory/persona.md`), learned facts and History live in plain files or Mem0 (`STEPOUT_MEMORY=off|files|mem0`; Mem0 needs `OPENAI_API_KEY`). Nothing a page or file said may write it, and nothing in `memory/mem0.py` may call Mem0's own model. After a `git pull` that changes `pyproject.toml`, `pip install -e ".[dev]"` again (`mem0ai` is the optional `[mem0]` extra; `[dev]` includes it).
- **Limits and the log:** `STEPOUT_TASK_CAP_USD` (per Run, default $1), `STEPOUT_MONTH_CAP_USD` (default $10), `STEPOUT_RETENTION_DAYS` (screenshots, default 30), `STEPOUT_LOG_LEVEL`; the app log is `<Home>/logs/stepout.log`. Model calls go through one retry policy ([ADR 0015](docs/adr/0015-one-retry-policy-at-the-model-port.md)): the SDKs' own retries are off.
- **Models:** Claude by default; `STEPOUT_STRONG_MODEL` and `STEPOUT_CHEAP_MODEL` re-point the two tiers through Pydantic AI ([ADR 0011](docs/adr/0011-pydantic-ai-as-the-plumbing.md)).
- **Verify UI features in the real page**, not only over the WebSocket: the first streaming check passed on frames and failed in the browser ([ADR 0013](docs/adr/0013-the-reply-streams.md)).
- Never read or print `.env` (it holds the API keys).
- **Home** (`paths.home()`): `STEPOUT_HOME` if set, else `data/` in a checkout, else `%LOCALAPPDATA%\Stepout`. Every data path lives under it, `.env` included (read from Home, then the repo's `.env` in a checkout only). The agents may not read it.
- **Releases and clean-room checks:** `docs/releasing.md` (tag `v<version>`, which has to match `pyproject.toml` and the README's install URL). `scripts/smoke_install.py` is what CI runs on a built wheel; `scripts/cleanroom.ps1` installs one as a new user would, in a throwaway folder (`-Phone` moves the real Tailscale phone link: read its help first).
- **Another Claude session may share this checkout** (the design work does). Do your edits in a `git worktree` (`git worktree add ../Stepout-<topic> -b <branch> origin/main`) instead of switching this checkout's branch under it.
- File access for the agents is set by `<Home>/config/grants.toml` (git-ignored in a checkout; template `grants.example.toml`). Only the User edits it, with `stepout grant`, the only thing that writes it.

## Engineering skills (in `.claude/skills/`, loaded on demand: don't preload)
- Changing an interface or module boundary (Channel, Role, Action, Gate) → `api-and-interface-design`.
- Anything touching files, the web, the browser or untrusted input → `security-and-hardening`.
- A change across several files → `incremental-implementation` (thin vertical slices, tests green at each step).
- Writing a Role's prompt or a context-heavy task → `context-engineering`.
- Using an external API or library (Anthropic, Playwright, aiohttp, Pydantic AI) → `source-driven-development`: check the official docs first.
- Orienting in a large codebase → `graphify query "<question>"` (graph in `graphify-out/`, rebuild with `graphify update .`). Not needed for small questions.

Provenance and what was left out: `docs/third-party.md`.
