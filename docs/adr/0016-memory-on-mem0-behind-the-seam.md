# 0016 — Memory: a Persona file, a learned store behind one seam, Mem0 as the primary store

Status: accepted · 2026-10-12 · built: Persona, History, the file store, the commands, Recollection, the extractor. Pending: the Mem0 adapter (see the plan, Unit 9).

**Decision.** Memory is two things behind one small interface (`memory.py`): **Persona**, a Markdown file the User owns and edits (`data/memory/persona.md`, one bullet per entry), and a **learned store** that holds facts the User stated and History (earlier tasks). The learned store is the seam [ADR 0003](0003-memory-files-first.md) asked for, with two adapters: plain files (`memory_files.py`, the baseline) and Mem0 (`memory_mem0.py`, primary once built). A Run is handed a **Recollection** (Persona plus the few relevant learned entries, about 2,000 characters at most) at its start; the Orchestrator alone sees it.

**What may write Memory.** Only the User (`/remember` adds a Persona line, `/forget` removes one entry) and the Assistant's own record of a Run (History), written by code from the Run: the User's request, the outcome, and what the hands did as **kinds and hosts only**, never a reply, a query, a path or any text a page or file could have worded. A Run that read a file leaves its request and outcome and nothing else. Facts are extracted from the User's own messages, through our Model port (metered, retried, Stop-aware, in the Ledger), never from replies, Findings, pages or files. A test plants an injection in a page and in a file and asserts Memory holds only the outcome.

**Why Mem0, and why the extraction is ours.** Mem0 is the store, the embedder and the search; Memory writes to it with `infer=False`, so Mem0's own model never runs. Letting Mem0 extract would put model calls inside a library where the Ledger, the cap, Stop and the retry policy ([0015](0015-one-retry-policy-at-the-model-port.md)) cannot see them. Mem0's current `add` is additive (it returns only ADD events), so little is lost. The file store stays so that "Memory off", "plain files" and "Mem0" are three Conditions to compare on the golden set.

**Rules that do not depend on the store.** Memory is data about the User, never an instruction or a permission (the Gate does not read it). It never fails or delays a Run: `recall` has a 3 s limit and `record_run` 5 s, and a failure is a Trace line, not an error. Every write is visible (the Trace, `/memory` with each entry's source) and forgettable. Deleting a chat removes what came from it. `STEPOUT_MEMORY=off` is a Run with nothing recalled and nothing kept.

**Limits.** Relevance is words in common then recency (files) or an embedding search (Mem0); neither is tuned. History names hosts, not pages, so "what did I read last time" is coarse by design.
