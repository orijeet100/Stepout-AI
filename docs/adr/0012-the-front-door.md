# 0012 — The front door: one cheap call before any agent money is spent

Status: accepted · 2026-10-07 · refined 2026-10-08

**Decision.** Every message that is not a `/command` gets **one cheap-model call** (Haiku, temperature 0) before the Orchestrator. It returns one of three things: *decline* (with a reason and what the assistant can do instead), a short *chat reply* (a greeting, thanks, or "what can you do?", nothing else), or *proceed*, together with the numbers of the earlier Exchanges in this chat that the message depends on. The Orchestrator then receives those Exchanges in full (request, the reply the User saw, a one-line "what was done") and **only those**; a new Task carries none. The "what can we do?" list is assembled from the capability registry. If the call fails or makes no sense, the message goes through carrying the last three Exchanges and the failure is recorded: the front door is never the reason a legitimate request dies. The one exception is a bad key, no key or no credit, because the Run's own calls would fail the same way: it says so and starts no Run.

**Why.** A regex decline list was tried first and measured: it missed 7 of 10 should-decline paraphrases (`send $200 to my landlord`, `wire money to John`) and wrongly declined 7 of 7 harmless requests that contained a trigger word (`how do I pay attention in long meetings`, `what is the cancellation policy for Airbnb`). One Haiku call answers both for about $0.002 a message, with no new vendor and no user text sent to a third party. Attaching the last N Exchanges to every message would resend history at every step, and let hostile text in an old reply reach unrelated tasks; linking by number gives a follow-up exactly its history. An Exchange from a tainted Run keeps its taint, so a Run that links it starts with the web closed.

**Rejected.** Keeping the regex as a first layer; a binary new/follow-up flag (cannot say that a message refers to something non-adjacent); a third-party screening service (deferred, not rejected: the front door sits behind a `Screener` port, so it can drop in as an adapter if a measurement says it is cheaper).

**Consequences.** Hard authority stays where it was: the read-only rule, the Gate and Grants. The front door only saves money and shapes the reply. A live labelled eval (`tests/data/screening_prompts.jsonl`, `pytest -m eval tests/test_live_screening.py`) keeps it honest: 97% agreement over two identical runs at the time of writing. Declining a request to *show* a secrets file is correct behaviour, not a false decline.
