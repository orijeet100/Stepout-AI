# 0008 — Laptop files: Grants, Off-limits, taint

Status: accepted · 2026-10-07 · Amends [0002](0002-laptop-only-v0.md) (laptop-file tasks no longer wait for V1)

The Assistant finds and uses the User's files itself — "upload my resume" means looking for it, not being handed it. Reach is set by **Grants**: folders the User allows, each with a mode (`metadata`, `read`, `organize`), kept per user in `data/config/grants.toml`. The default is none; the owner may grant their whole profile. Only the User edits Grants — never the model or the chat, because an injected instruction could otherwise widen its own reach. A built-in **Off-limits** list (browser profiles and password stores, `.ssh`/`.aws`/`.env`/key and wallet files, password-manager vaults, `AppData` credential areas, system folders, and the Assistant's own folder) can never be granted; the own folder is excluded so the Assistant can't read its API keys or rewrite its own config, Memory or Ledger. The Files module enforces Grants itself, not only the Gate, so the same code stays safe later as the remote helper. Reading file contents **taints** the Run: every outward Action then needs an Approval showing what goes where. Organizing is plan, Approval, execute, undo journal — never overwrite, never delete.

Considered: handing Documents every time (rejected: not the assistant the User wants); Docker mounts as the control (no daemon running, and Grants enforce the same thing in-process); a hard folder allowlist only (rejected: the owner wants broad reach, so the controls sit on taint, Approvals and Off-limits instead). Consequence: a whole-profile Grant widens the blast radius of a successful prompt injection; the taint rule, read budget and Approvals are what contain it, and `read` Grants send file contents to the model provider (recorded as Egress).
