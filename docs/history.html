Design and scope

2026-10-07 · 00:43 → 00:55 · 2 commits · +1212 −259

Aimed at

Know what to build and why before writing code: the claim to prove, the requirements, the module boundaries, a shared vocabulary, and the decisions that are expensive to reverse.

Achieved

The design set was committed in two steps: a first pass (brief, requirements, architecture, roadmap S0-S11, glossaries, ADRs 0001-0006), then a scope change that added laptop files, brain-and-hands and the React page (ADRs 0007-0009). ADRs 0001-0006 are dated 2026-10-06; both commits are 2026-10-07.

Decided 9
  • Hand-write the parts we measure (router, agent loop, memory, gate, run manager); borrow plumbing (Playwright, the Anthropic SDK, Pydantic, pytest, aiogram). No agent framework.Why: The goal is to learn how production agents work; wrapping the core would hide exactly those parts. adr/0001-from-scratch.md
  • V0 is one Python process on the laptop: no Docker, cloud, containers, email or credentials. Browser tasks use a fresh isolated context; navigation only to http(s) on public hosts.Why: Docker was not running and adds little protection while the agent has no file tool; the real risks (prompt injection, bad actions) are handled by the Gate. adr/0002-laptop-only-v0.md
  • Memory starts as plain files (Persona, History, Notes) behind recall / remember / forget; mem0 comes later as a second store, compared on the golden set.Why: Memory is what the headline metric tests, so owning the first version makes every improvement explainable; 'memory off' is just an empty folder. adr/0003-memory-files-first.md
  • Drop 'replay with zero model calls'. The headline metric is human interventions per task across repeated attempts, against a memory-off control.Why: The goal is an assistant that finishes jobs from a phone and improves with experience, not a cost trick. No model is trained; improvement comes from recall. adr/0004-drop-zero-model-replay.md
  • Two bounded contexts, Assistant and Evaluation. Evaluation drives the Assistant only as a Channel and reads its Ledger.Why: The proof must never shape the product, and the Assistant must never grade itself. adr/0005-two-bounded-contexts.md
  • SQLite for runs and the Ledger (one Store module, user_id on every table, a unique constraint for at-most-once Actions); Markdown for Memory.Why: Intending an Action and writing its Checkpoint must be one atomic transaction; JSONL cannot do that, and Postgres is a server for one user. Postgres comes with a second machine or many Users. adr/0006-sqlite-for-runs-and-ledger.md
  • Every Action and Result is plain serializable data ('brain and hands'), enforced by a round-trip test.Why: In V1 the hands (browser, files) can move off the laptop without a redesign. adr/0007-brain-and-hands.md
  • Laptop files only through Grants (folders the User allows, in grants.toml, edited only by the User) and a fixed Off-limits list. Reading file contents Taints the Run.Why: 'Upload my resume' means the Assistant looks for it itself. If the model or chat could edit Grants, an injected instruction could widen its own reach. adr/0008-laptop-files-grants.md
  • The web page is React (Vite + TypeScript) in web/, served by the Python process over aiohttp.Why: A plain HTML page would be thrown away; aiohttp is already installed through aiogram. adr/0009-react-web-page.md
Built and changed 3
