# M3 result — the Browser agent, and a leaner loop

Date: 2026-10-07 · Plan: [`../game-plan.md`](../game-plan.md)

## What's built
- **`browser.py`** — the installed Chrome, headless, through Playwright (no browser download). One fresh context per Run: no cookies, no logins, no downloads, no service workers. The agent can only `open` a url, `click` a numbered link from the last page, or read `more` of the same page: it cannot type, press buttons or submit forms.
- **Network policy on every request** (the Fetcher's policy, FR18). Playwright runs a route handler once per request chain and lets the browser follow redirects itself, so the handler fetches each request with `max_redirects=0`; a main-page redirect is answered with an empty page and the next hop is checked by us before any request is made. Page WebSockets and media are blocked. Verified against real Chrome and two local servers: the "private" server received **zero requests** via direct link, redirect, redirect chain, page link, image, `fetch()` and WebSocket.
- **Browser Role** (Sonnet 5, one `browse` tool); a JPEG screenshot per page, served only by exact run-id/number and shown as a thumbnail in the live trace. Only a Role's newest two page views stay in its notes.
- **Leaner orchestration:** a plan starts its own first step (one Sonnet call fewer per Task), and every Role's state now ends with "the results are above, answer if they are enough", which removed the repeated first call every specialist made. Identical repeated actions are not re-run.

## Not yet done
- Not re-checked by eye in the web chat: the screenshot thumbnail in the live trace (route and tests pass; the page builds).
- Stop during a page load is untested; Browser retries after a navigation timeout are not implemented.
- Screenshots accumulate in `data/runs/` with no cleanup.
- Known ceilings: a subresource redirect (e.g. a CDN hop) is dropped, not followed; DNS is checked once per host:port per Run.
