# M2 result — the Files finder

Date: 2026-10-07 · Plan: [`../game-plan.md`](../game-plan.md) · ADRs: [0008](../adr/0008-laptop-files-grants.md), [0010](../adr/0010-one-loop-many-roles.md)

## What's built
- **`files.py`** — `list`, `find` and `count` over the User's disk: names, sizes, dates and counts only, read-only, Windows paths. Every path the model supplies is shape-checked (no relative, UNC, device `\\?\`, alternate-stream or `..` paths), **real-path resolved** (links, junctions, 8.3 short names), then checked against the fixed **block list**, then the **Grants** in `data/config/grants.toml`. A missing grants file means no access; a bad mode refuses to start.
- **Block list (code, not config):** `.ssh`, `.aws`, `.azure`, `.gnupg`, `.kube`, `.docker`, `.env*`, `*.pem`, `*.key`, `*.pfx`, `id_rsa*`, `*.kdbx`, wallet files, `.git-credentials`, `.npmrc`, `.netrc`, Chrome/Edge/Firefox/Brave profiles, Windows credential and vault folders, password-manager folders, the Recycle Bin, `C:\Windows`, `C:\Program Files*`, `C:\ProgramData`, and the Assistant's own folder. No grant widens it.
- **Walks** never follow links, skip blocked folders, stop at 60 s or when the User presses Stop, and run in a thread so the page and the Stop button stay responsive. File names are stripped of control characters and capped before they reach the model.
- **The Files agent** (Haiku 4.5, one `files` tool, Gate-enforced): the Orchestrator can plan a `files` step. Your `grants.toml` grants `C:\` and `D:\` in read mode (metadata operations work in either mode; `read` is for the Reader in M4).

## Verified live (real API, your D: drive, 2026-10-07)
| Request | What happened | Cost |
|---|---|---|
| "How many files are on my D drive, by type?" | plan → Files agent `count D:\` → **1,625,029 files in 176,705 folders (105.7 GB) before the 60 s limit**, reported as a partial count (lower bound) | $0.027 |
| same, Stop pressed ~12 s in | the walk ended, "Stopped by you." within seconds | $0.016 |
| "List the files inside D:\Stepout AI and show me .env" | `Denied: off-limits`; the answer says it is blocked by fixed safety rules and offers no workaround | $0.005–0.024 |

Offline: **118 tests pass** — 65 for the Files module (17 denied-path cases × 3 operations; junction, symlink and 8.3-short-name escapes; the block list beating a whole-drive grant; clock and Stop limits; name hygiene; grants parsing) plus the wiring. A mutation check (disabling real-path resolution) made a junction list the outside folder, so the escape test is real.

## Deviations from the plan
- **`stat` is folded into `list`** (a file path lists as one entry with size and date). One `files` tool with an `op`, per the tool-design guidance.
- **The Gate allows the `files` kind; the Files module enforces paths**, because resolving a real path needs the disk and the Gate is pure.
- Grant `mode` is parsed and validated but only the Reader (M4) will enforce `read`.

## Found by live testing, fixed
The first answer to a denied request suggested running as administrator, and a markdown table rendered as raw pipes. Prompts now say: blocked means blocked (no workarounds), use bullet lists not tables, only offer what the team can do, and name the always-blocked categories so the Orchestrator never offers them.

## Found by live testing, fixed (second round)
- **`find` on a whole drive is refused** ("too broad: list the drive, search the likely folders, or ask the User"). Live: "find my resume on D:" listed the drive, searched Documents/Desktop/Downloads, found nothing and **asked which folder to look in**; with the User's hint ("a folder called 2026 resume, on C") it found the folder and the resume PDF in 10 steps for $0.034.
- **Quotes were part of the search pattern** (`"resume"` can never match a file name), so the agent looped on empty results. Patterns now ignore quotes, and several quoted or comma-separated terms mean "any of them".
- **Identical hand actions are not re-run** (a model call still happens, the disk call does not); and the Orchestrator is told to delegate right after planning (it had been writing its plan twice).

## Known gaps (ceilings, not bugs)
- **60 s covers only part of a big drive** (the D: count reflects the folders it reached first), and there is no progress display during a walk. *Decided by the User: no full-drive scans; keep the cap and partial counts. Smarter search (ask for a hint, rank folders, prune junk) is a later item in the game plan.*
- Names and paths from `list`/`find` are sent to the model provider (counts by extension are only numbers); file contents never are in M2.
- Block-list hidden counts reveal that something blocked exists (not what).
- Check/use race: a folder swapped for a junction between resolve and walk is not caught (the walk itself never follows links).
- The Orchestrator sometimes writes its plan twice (the re-plan limit bounds it).
