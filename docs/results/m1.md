# M1 result — Orchestrator, Plan, live Trace, Stop

Date: 2026-10-07 · Plan: [`../game-plan.md`](../game-plan.md) · ADR: [0010](../adr/0010-one-loop-many-roles.md)

## What's built
- **One loop, two Roles** (`runner.py`, `roles.py`): the Orchestrator (Sonnet 5; tools `plan` / `delegate` / `answer`) and Direct (Haiku 4.5; web search + fetch). The Orchestrator answers trivial requests itself, otherwise writes a Plan (1–3 steps), delegates one step at a time, re-plans at most twice, and reports.
- **Shared per Run:** one $1.00 Budget (`STEPOUT_TASK_CAP_USD`), a 3-search cap passed to the provider as `max_uses`, one Gate (a Role may only take its own Action kinds), one Ledger. A specialist sees its goal and what it has learned, never the Orchestrator's plan.
- **Ledger events carry `role` and `parent`** (migration 0002; migrations are now tracked with `PRAGMA user_version`, so existing databases upgrade in place).
- **Live Trace:** every plan snapshot, step, return and stop is recorded to the Ledger and streamed to the Channel (`trace`); the web page shows the plan checklist and indented events live, folded above the reply afterwards. **Stop** sets a flag the Runner checks between steps. The CLI prints the same events as one-liners.
- **Source links kept (FR4):** citations from web search become a `Sources:` list in Direct's Finding and the Orchestrator is told to keep links.

## Deviations from the plan (and why)
- **No forced tool choice.** The docs say newer models (Opus 5.5, Sonnet 5.5, …) reject `tool_choice: any`; tool choice is automatic and a text-only reply counts as the answer.
- **Basic web search (`web_search_20250305`).** The 20260209+ versions default to dynamic filtering through code execution, which Haiku can't use.
- **One `step` event per model call** (action + verdict + cost) instead of separate model_call/verdict/action rows; `plan`, `return` and `stop` are the other kinds.
- **No `ask_user` yet.** Pausing for an answer needs S3; the Orchestrator can ask in its final reply.

## Known gaps (ceilings, not bugs)
- Stop takes effect at the next step boundary, so during a long search call it can take ~20 s.
- A search that ends with `pause_turn` is not resumed; the partial text is returned (empty text fails the step).
- A malformed tool call from the model raises and is caught by the session guard ("Something went wrong") instead of being fed back.
- Intake's cheap-model call is in the Ledger but not in the cost shown in the reply.
- The web channel keeps chat and trace history in memory (unbounded) until restart.
- The Orchestrator sometimes over-plans (a 2-step plan where 1 would do); the Trace makes it visible, a Verifier or prompt tuning comes later.
