**What.** Each tool is now a capability module under `src/stepout/capabilities/`: `fetch`, `files`, `browse` and the provider-side `web_search`, registered in one list (`ALL` in `__init__.py`). A capability is a subclass of `Capability` (`base.py`) that sets `name`, `blurb`, `tool` (the schema) and `action` (its Pydantic Action) and overrides only what differs from the defaults: `run`, `summary` (the Trace line), `check` (an extra Gate rule), `repeat_guard`, `compact` (trim old notes). It reaches its hand and the Trace through a `RunContext` (`hands` by capability name, `cancelled`, `emit`), never by importing the Runner. Consequences elsewhere: `domain.Action` is the discriminated union of the registry's Actions plus `plan`/`delegate`/`answer` (and the legacy `search`); `FetchAction`, `FilesAction`, `BrowseAction` are re-exported from `domain` so imports keep working; `model.py` keeps only the control tools and asks the registry for the rest, and `ModelResponse.action` is a plain `BaseModel` so a capability registered after import (the test's `echo`) is accepted; `gate.check` asks the capability's own rule after the Role check; the Runner has one generic arm for any capability. `PlanStep.role` and the plan tool's role enum come from `ROLES` (`roles.SPECIALISTS`); `roles.py` no longer imports `model.py` (it now holds the model ids, `model.py` prices them), and `Role.actions` asks the registry which tools the provider runs. `capabilities.blurbs()` returns the one-liners B3's front door will use.

**Why.** [Refactor to capability modules before adding capabilities](2026-10-07-capability-modules-first.md): adding a tool meant editing five files; now it is one file and one line.

**Alternatives.** A `Protocol` instead of a base class, as the hand-off sketched: every capability would then repeat four default methods; a base class with defaults keeps a new capability to what is different about it. Building the Action union lazily or per request: slower and hides the schema; an import-time union plus a loose `ModelResponse.action` is simpler. Moving `Runner`'s three hand arguments into one `hands` dict now: no caller needs it yet, so `fetcher`/`files`/`browser` stay (B4 adds a hand and can decide).
