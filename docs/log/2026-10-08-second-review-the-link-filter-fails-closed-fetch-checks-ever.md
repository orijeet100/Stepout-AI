**What.** A second, independent correctness review (read-only, of everything in C3) found that the first round's link filter could be bypassed, and several smaller things. Fixed here, each with a test that fails without the fix. It supersedes the filter described in [review-fixes](2026-10-08-review-fixes-fetch-checks-every-redirect-hop-a-tainted-answe.md); the rest of that entry stands.

1. **The link filter could be bypassed (high).** The first version listed link shapes (`[w](url)`, `<url>`, reference definitions) and the page parses markdown more loosely. Each of these left a live link in the page, checked by rendering with the page's own renderer: `[a](mailto:x@evil?body=SECRET)`, an uppercase scheme (`HTTP://`, `<HTTPS://…>`), an entity or backslash in the scheme (`&#104;ttps://`, `https\://`), nested brackets, link text across a line, a reference definition in a quote or list or on the next line, and (found while fixing it) the removal marker itself, which read `[link removed: host]` and joined a `(https://evil…)` that followed it into a live link. **Now it fails closed:** `links.py` recognises ONE shape, `[words](https://address)` in lowercase with nothing odd in it, and keeps it only if the address is allowed; a recognised link to any other address becomes `words (link removed: host)`; then every other `[` is escaped as `\[` and every `<` as `&lt;`, so nothing else can become a link however it is written. A form the filter never heard of shows as plain text. `tests/test_links.py` has the 19 shapes (and the marker attack) and **renders the filtered text through the page's own react-markdown config** (`tests/support/render_links.mjs`, a copy of `web/src/Reply.tsx`'s settings; skipped without node and `web/node_modules`) and asserts no link to the bad host and no `mailto:` appears, that an allowed link still does, and that the unfiltered first shapes really are live links (so the check can fail).
2. **Cubic backtracking (medium).** The old pattern took 4.6 s on 6,000 characters of `[a](https://` repeated and 30 s on 12,000: a poisoned file could freeze the app's event loop. The new one is bounded on both sides; the test filters 40,000-character hostile strings in under a second. The hostname lookup for the "link removed" note no longer raises on a malformed bracketed host (it raised `ValueError` after the Run had been recorded and before the reply was sent).
3. **A bare address could be laundered into a link (medium-low).** An earlier tainted reply may show an address as text (bare addresses are left alone); a follow-up that built on it could write it as a markdown link and it passed as "from elsewhere". For a tainted earlier reply only the links that survived the filter are allowed now (`links_in`), not every address written in it.
4. **A skipped `open` could leave the Role on the wrong page (medium).** open LIST, click into a listing, open LIST again: the old view was still in the notes (two stay in full), so the second `open` was skipped as a repeat while the browser stood on the listing, and the next `click N` followed link N of the wrong page. A capability can now say it is `stateful` (`browse` does): its repeat is skipped only straight after the identical call. A files listing, a read or a fetch do not depend on what ran in between and keep skipping repeats.
5. **Fetch (low-medium), three things.** (a) A redirect to something that is not an address (`http://a.example:abc/`, a control character) raised out of the Fetcher and killed the Run; it is a `BlockedUrl` now. (b) The network policy ran its DNS lookup on the event loop, up to six times a fetch; it runs in a thread. (c) The policy checked the one address `gethostbyname` returns, but the connection may use any of a host's addresses: a host with a public first record and `127.0.0.1` or `::1` in another passed. It uses `getaddrinfo` and every address must be public (the DNS-rebinding gap between check and connect remains, as documented in `fetch.py`).
6. **The acceptance harness could mis-green (medium).** `web_allowed: true` only permitted a web step. m3 and m4b now need at least one allowed web step (`web_required`), so a reader-first order that gets the posting refused and answers "I could not open it" fails; the follow-up and m4a/m4b must really be tainted (`expect_tainted`), so a follow-up the front door failed to link cannot pass by being polite; m2's counts must sit next to their types (`contains_regex`; `txt 3, pdf 4` no longer passes). The report is rewritten as each query ends, so an interrupted live run keeps what it already paid for. Negative controls for each.
7. **`PORT`** is used only if it is a number (a stray `PORT` from another tool no longer crashes the start).

**Considered, not done.** Streaming the Fetcher's body to cap the download (the 2,000,000-character cut is applied after `response.text` has read everything): pre-existing, a ceiling, noted. Filtering untainted Runs' links: a file name can be attacker-controlled text from a `files` step; accepted before and still (web pages and names are not file contents). Connecting to the vetted IP through a custom transport (the full answer to DNS rebinding).

**Evidence.** Offline suite 483 passed. Mutation-checked: no escaping of `[`, no escaping of `<`, the marker back to brackets, laundering allowed again, only the first resolved address checked, the policy back on the loop, the stateful rule ignored or applied to everything: each fails a test. Files: `src/stepout/{links,fetch,runner,app}.py`, `src/stepout/capabilities/{base,browse}.py`, `scripts/acceptance.py`, `tests/data/acceptance.jsonl`, tests.
