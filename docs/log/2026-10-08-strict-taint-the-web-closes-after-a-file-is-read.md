**What.** Cycle C2, slice 4: the rule that makes the Reader safe to ship, in its **strict, safe-by-default form** as asked. Once any `read_text` has returned file content in a Run, **the Gate refuses every web action for the rest of that Run**, whichever Role asks, with a message the Role can act on: *"the web is closed for the rest of this task: the contents of <file> were read, and what a file holds must never be sent out through a URL. Work from what you already have, and say plainly what you could not do."*
1. **State.** `RunState` (shared by every Role in a Run, introduced for the read budget) gains `tainted` (the reason, or empty) and `taint(why)`; the first reason is kept. A new Run starts clean.
2. **When it is set.** `read_text` sets it **only when file text was actually handed over** (`ReadResult.content`). A refusal (`Denied`, `Limit`), a scanned PDF with no text, an encrypted one, an empty file and a binary all return nothing from the file, so they taint nothing and the web stays open: a failed read has nothing to leak, and tainting on it would make a typo in a path cost the whole task its web access.
3. **How it is enforced.** A capability declares `reaches_web = True` (`fetch`, `browse`, `web_search`); `gate.check` refuses any capability with that flag in a tainted Run. The rule names no capability, so a new web tool is closed by setting the flag (noted in `CLAUDE.md`). `web_search` is run by the provider and never reaches the Gate as an Action, so the Runner stops offering it instead: a tainted Run's model calls carry `max_searches=0`, which the adapter already treats as "no web search tool".
4. **What stays open.** The disk (`files`, further `read_text` within its budget), the Orchestrator's own tools and answering. The Orchestrator is told the rule and the reason in advance ([the Reader Role entry](2026-10-08-the-reader-role-and-the-reading-last-rule.md)): web steps first, reading last.

**Why.** File contents are written by anyone and may carry instructions (LLM01). The system prompt is not a security boundary, so the boundary is in code: the way out of this process is the network, and a Run that has read a file can no longer use it. That holds even if a hostile PDF persuades the Reader or the Orchestrator, even if secret screening misses a secret, and without anyone having to recognise the attack. It is deliberately blunt: a task that needs the web *after* a read is refused and has to be asked again as two tasks. That cost is accepted for now because the safe default matters more than the convenience.

**Not built here, on purpose** (cycle C3). Relaxing it to "sites the User named"; carrying taint across follow-ups (an Exchange that read a file marks the next Run that links it); the poisoned-PDF test with the outbound-request count; a trace/Ledger event for the moment a Run becomes tainted (the refused step already shows the reason).

**Alternatives.** Approvals (the User confirms each outward action, showing exactly what goes where): the long-term design (ADR 0010), but Approvals do not exist yet. A model-based judgment of whether a request is dangerous: the thing a prompt injection attacks. Closing only `fetch` and `browse` by name: a future web tool would be open by default; the flag makes closed the default for anything that declares it.

**Evidence.** Offline suite **342 passed, 7 deselected** (333 before; +9 in `tests/test_taint.py`). Gate: before a read every action is allowed as before; after, `fetch` and `browse` are refused with the message above while `files`, `read_text` and `answer` are not; exactly `web_search`, `fetch`, `browse` declare `reaches_web`; the first reason is kept. Capability: the read of a real PDF taints with the file's path; a blocked `.env`, a scan, an empty file, a binary and a missing file do not. Through the real Runner, Gate and Reader (real files, a scripted model): after the CV was read, a Direct agent's `fetch` is refused, the Fetcher is never called, its next request says why, the web-search budget is 0 on every later model call and 3 before; a Browser agent's `browse` is refused and the browser is never opened; web first and reading last works with nothing refused; a read that returned nothing leaves the web open and search offered; a second task on the same Runner starts clean; a Run that never reads is unchanged. **Mutation-checked:** removing the Gate rule, offering search again, tainting on every read and never tainting each break the specific tests meant to catch them, and the sources were restored byte for byte. Files: `src/stepout/{gate,runner}.py`, `capabilities/{base,fetch,browse,web_search,read_text}.py`, `tests/test_taint.py`.
